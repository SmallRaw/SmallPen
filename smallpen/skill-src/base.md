## SmallPen operation rules

Use the supplied CLI path, otherwise `smallpen` on PATH. The installed CLI's help/schema governs available fields and flags, even when its version matches this Skill; source examples can differ from the installed build. Discover operations with `help`, then `help OBJECT`, `help OBJECT ACTION`, and the returned schema queries. Read only the action and input fields needed now; use returned IDs, not invented selectors. Put write JSON in files. Honor the user's authoring tool choice; read-only App inspection does not authorize App edits.

Start with one target and compact text for navigation, then use the installed CLI's supported outputs. Three design outputs have distinct roles: **specification** (`view --as spec` / `export --format spec`) supplies implementation constraints, native geometry, Token/component sources, instance overrides and diagnostics; **wireframe** shows spatial structure on an approximate character grid; **PNG** shows high-fidelity appearance for visual acceptance. Implement from constraints such as `height=hug`, not the resulting pixel height alone. Compare `layout.hash`, revision and selection across outputs. `export --format png --evidence` produces all three and JSON evidence from one native solve. `--element` expands selected-node details. Unknown geometry stays `?`/`partial` with a reason; never infer actual coordinates from seed bounds, bindings from equal values, or business rules from appearance. Coverage proves only the listed combinations. Search large result files instead of loading all JSON: `resultFile.text.path` contains readable specifications. Preserve LF/spaces and display wireframes in monospace without soft wrapping. A text-only caller may export PNG but must not claim visual inspection.

Supply a stable batch ID before retryable edits, reuse it only with identical input, and read the write receipt. Follow scoped error recovery and current schemas. An explicit reverse edit is a new guarded write; it is not history rollback. Read check issues, skipped coverage and rendering limits before describing a result as verified.

These are tool rules. The scene below defines how to use the tool for this task.
