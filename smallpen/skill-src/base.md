## SmallPen operation rules

Use the supplied CLI path, otherwise `smallpen` on PATH. The installed CLI's help governs the format and commands, even when its version matches this Skill. A package is a folder of HTML files that you edit directly: `smallpen help rules format` lists the files, elements and attributes; `smallpen help rules classes` lists the Token variables and classes. Read only the part you need now.

Edit with your own file tools. After every edit run `smallpen check PACKAGE`: it reports each problem as `file:line:column severity code message` with the fix, and exits 1 on errors. `check` is also the gate: what passes becomes the accepted version; with errors, changed files that keep the package valid are accepted and the files with errors are listed as `rejected`. Fix every error, or run `smallpen check PACKAGE --revert` to put the rejected files back to the accepted version (rejected new files are removed). When several agents edit one package, revert only your files with `--revert --file PATH`. Look at the result only after a passing check. Write Tailwind v4 classes, never `style`, `<style>` or `<script>`; they mean what Tailwind and CSS mean. Give each design decision a Token named for its role and use its class (`bg-surface`, `p-card`, `type-label`); write a bracket literal (`w-[240px]`) only for a one-off. Tailwind's default scale (`p-4`, `rounded-lg`, `text-sm`) reads as the same raw values, not Tokens, so it is no design system. `check` names a raw value that recurs. Elements are known by `data-name`; files hold no ids and no positions that layout derives. Honor the user's authoring tool choice; read-only App inspection does not authorize App edits.

Start with one target and compact text for navigation, then use the installed CLI's supported outputs. Three design outputs have distinct roles: **specification** (`view --as spec` / `export --format spec`) supplies implementation constraints, native geometry, Token/component sources, copy overrides and diagnostics; **wireframe** shows spatial structure on an approximate character grid; **PNG** shows high-fidelity appearance for visual acceptance. Implement from constraints such as `h-fit`, not the resulting pixel height alone. Compare `layout.hash`, revision and selection across outputs. `export --format png --evidence` produces all three and JSON evidence from one native solve; its `--output` is a prefix without a file extension, and the reply names the actual files. `--element` expands selected-node details. Unknown geometry stays `?`/`partial` with a reason; never infer actual coordinates from seed bounds, bindings from equal values, or business rules from appearance. Coverage proves only the listed combinations. Search large result files instead of loading all JSON: `resultFile.text.path` contains readable specifications. Preserve LF/spaces and display wireframes in monospace without soft wrapping. A text-only caller may export PNG but must not claim visual inspection.

People save changes in the App; the App rewrites the page or component file they changed in the standard layout. Keep the latest `revision` any command reports, and run `changes PACKAGE --since REVISION` before editing again. Read check issues, skipped coverage and rendering limits before describing a result as verified.

The `--components` catalog shows representative samples: read `preview.components` for displayed and omitted variants. A named component's PNG/wireframe includes every variant in both view and export; `--variant` or `--element` narrows the target. For view and export, `--element` also accepts the actual root name when no descendant has that name; omitting it selects the whole target.
