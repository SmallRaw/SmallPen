# CLI 与场景 Skill

SmallPen 是通用设计画布和素材工具。CLI 提供操作，Skill 提供场景里的使用规则。

## CLI

AI 不安装 Skill，也能通过 `help` → `help OBJECT` → `help OBJECT ACTION` → 返回的 schema 查询独立学会操作。参数、输入格式、默认值、覆盖规则、错误恢复和能力限制由 CLI 说明。

`project init PATH` 直接创建空白项目：一个 Base 画板和 Theme/Default，没有初始 Token、组件、业务流程或两端页面。PATH 可以是 `.smallpen` 路径或新工作目录；`--layout foundation-product` 可创建一组空白 Foundation/Product。拒绝已存在的目标。公开入口不收集业务问卷，也不写问卷状态。

旧 `init --answers FILE` 只为旧脚本保留完整 Brief 的显式导入。它不会问询、收集零散答案或恢复状态；新调用者使用 `project init`。既有设计包及 App 的空白建包行为保持兼容。

`help rules` 按需说明主题、Token、组件、目标、输出、写入、检查和连接的技术规则。旧 `help workflow`/`schema workflow` 查询同一组技术规则，不再提供应用制作流程。

主题组由项目定义。省略 `--theme` 使用项目默认值，明确的 Scenario 和 `--theme` 依次覆盖指定组；查询不保存组合，也不采用或修改 App 当前选择。值修改仍使用现有共用模型，不另造 Skill 专属逻辑。

查询从小数据开始，输出紧凑 JSON。大结果放入可搜索的结果文件；文字描述和线稿先行，PNG 明确请求。文件名随机且格式固定，半小时前的旧临时文件按现有规则清理；正式交付用 `--output`。

## 生成与安装

共同基础维护在 `skill-src/base.md`，应用规则维护在 `skill-src/ui-design.md`。`npm run build:skills` 从源码取得可变技术规则，组合成独立可安装的 `skills/smallpen-ui-design/SKILL.md`。生成结果不依赖其他 Skill，也不引用仓库外的业务说明。`npm run check:skills` 发现过期产物而不改文件；`build:cli` 同步生成并附带成品。

共同基础不复制全部命令或 schema，具体操作仍通过 CLI 查询。以后增加场景时内嵌同一份基础并追加自己的流程。

## 应用设计

1. 首次确认软件用途、用户、主要任务、预计平台和首个交付端。信息完整时直接继续；关键缺项先问，一般视觉细节由 AI 决定并记录。
2. 项目维护一份 `DESIGN.md`，记录确认的需求、假设、设计规则、结构差异和验收目标；后续更新同一份文件。
3. 先复用/定义 Token，再制作组件及变体，最后组装页面。AI 在制作时完成有用的 Token 绑定，避免交给开发补绑定。
4. 同一业务内容优先共用页面，通过 Token 组合改变宽高、间距、字体和样式；局部结构差异优先变体；整体结构或交互确实差异很大才增加配置或页面，记录理由。缩小视口不允许默默删减能力。
5. 使用同一目标及组合查看、检查和导出，核对实际绑定、组件引用、业务能力和检查覆盖。按需要连接元素触发和目标，验证具体导航步骤。
6. 交付可编辑设计文件、需要的导出和检查说明。原型跳转不等于真实输入、数据保存或应用代码。

当前 Token 能改变已绑定数值，不能切换可见性、布局方向、节点树或组件变体。标准壳子可由共享部件围绕业务实例组装，当前实例 API 没有任意内容插槽。Skill 要如实报告工具缺口，不假定缺失能力或用整页复制代替复用。

## 后续场景

动画素材主要供 HyperFrames 使用；具体流程和风格统一需求后续细化。漫剧角色设定是多素材、多角度、多动作画板，不要求 Token，暂按用户从外部生成素材后导入组织的流程考虑。这两项的草稿放在 `skill-src/drafts/`，不作为可安装成品。

## 验收

用现有 CLI 黑盒入口验证空白建包、参数发现、无问卷状态、持久化、检查和导出；用生成/检查命令验证确定输出及过期检测。已有主题默认、组合覆盖、App 矩阵和投影规则继续使用同一逻辑。自动检查有效不代表视觉或业务验收通过。
