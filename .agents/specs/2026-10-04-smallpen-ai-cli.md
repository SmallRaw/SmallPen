# SmallPen AI CLI 完整工作流规格

日期：2026-10-04。本文根据完整需求讨论整理，仅保存在本地。状态：领域流程已实现；CLI 使用常规命令、逐层 help/schema 查询。Code Mode 已取消。用户已确认 Testing Decisions 中的测试边界。

## Problem Statement

SmallPen CLI 完全供 AI 使用。AI 应能只靠一个 CLI 的 help、schema 和返回结果，完成项目初始化、Token 设计、组件设计、页面绘制、交互连接、检查、导出和后续维护。现有入口存在职责重叠、说明不足及输出过大的问题；AI 容易把设置、查看、检查和导出混为一谈，或为修改一处而提交整份设计数据。

Token 主题组由项目自由设计。平台、明暗、语言等只是可能的维度，不能成为固定必填参数。CLI 必须清楚说明项目默认项、显式选择、原始定义、解析结果及覆盖来源，并与 App 共用规则。CLI 的本次查看组合与 App 当前选择独立，读取不能改变 App 当前或保存的选择状态。

完整工作流还需要组件变体与实例内容的正确区分、局部修改、素材和字体管理，以及真正可设置的页面交互。画出流程图或保存交互字段，不能证明原型流程能够按配置执行。AI 需要理解已有页面上的交互元素及连接关系，并能设置、修改和检查这些关系。

AI 不应承担内部结构修补、引用维护或布局计算。程序负责这些细节，AI 通过文字描述、文字线稿、真实 PNG 和有明确覆盖范围的检查结果理解设计。返回内容也必须控制大小，让 AI 可以逐步读取。

## Solution

提供一套自描述、职责清楚的 AI CLI：设置操作写入设计，读取操作查询定义，查看操作解释当前结果，检查操作返回问题及覆盖范围，导出操作生成文件。help 与 schema 使用同一份实际命令契约，说明每个动作的目标、参数、默认规则、限制、结果和下一步操作。

AI 的工作顺序为：理解项目与已有资产，确定主题组和 Token，完成可复用组件及变体，组成页面，设置交互连接，检查项目所需的领域组合，按需导出交付，再按明确范围维护。AI 必须先查可复用 Token 和组件，再补缺项；工具仍允许直接值。

App 和 CLI 共用领域规则及设计数据逻辑。CLI 未传主题选择时使用项目默认，显式选择只覆盖指定组；组合只用于本次调用，不新增保存组合的对象。组件默认查看与检查使用 App 主变体，页面实例使用自身保存的变体选择。

查看默认采用简洁文字。文字线稿保留换行和对齐空格；真实 PNG 按需生成。流程以已有页面上的元素、触发方式、动作、目标和联动为中心，支持 AI 配置连接及按需逐步验证，默认只返回交互关系和每步变化。

## Implementation Decisions

1. **职责与术语。** CLI 专供 AI。设置、读取定义、查看结果、检查和导出各有清楚职责；help 推荐一个明确动作入口，不用含糊的总入口包办所有行为。参数使用稳定目标标识，程序承担数据结构维护与计算。
2. **模块边界。** 涉及 CLI、共享 core、local-package、penpot-adapter 和 App 前端适配。共享 core 维护领域操作、默认选择、Token 解析及必要投影；CLI 和 App 各自处理输入输出和宿主状态。local-package 维护持久化、版本及原子写入。仅修改满足实际需求所需的模块。
3. **统一命令契约。** help、schema、输入校验与实际行为使用同一份契约。契约描述合法字段、目标、默认来源、约束、输出、错误和下一步。AI 不应为简单编辑提交完整内部对象，也不应必须读源码才能发现能力。具体命令拼写按完整能力整理，不以此前部分入口冻结最终接口。
4. **项目自定领域。** 主题组对应项目已有 Token Domain 和原生顶层 Token Set Group；组内选项对应已有 Token Variant、原生 Token Set 及配对主题。Token 名字的层级与主题组是不同概念，组件变体也不是 Token 主题。项目可没有主题组，平台、明暗、语言等均为可选示例。
5. **组合与默认。** 未传主题选择时使用项目默认；传入某组选项只覆盖该组，其他组继续使用默认。新增组、默认项创建与配置、删选项后的行为、旧包兼容和覆盖优先级均与 App 共用逻辑。项目默认不是 App 当前激活的选择；显式设置默认是写操作，临时组合不是。
6. **选择隔离。** 本次组合不新增保存对象，不写回 App 当前或保存的选择，不自动载入 App 当前组合。每次读取、查看、检查、导出和流程验证报告完整实际组合及目标。已存在的页面配置按 App 原生模型维护，但不能借此引入独立保存 Token 组合的必选流程或新概念。
7. **Token 原始定义与解析。** 分开提供各单元格的原始定义和本次组合的有效值，返回来源与覆盖关系。同名 Token 在不同领域是独立定义，有效值按 App 的 Set 顺序覆盖，后面的活动 Set 优先。空格不自动继承 Default；未设置与合法零值、false、空字符串不同。
8. **共享 Token 写入。** 新增行在当前领域所有原生选项 Set 中创建独立 Token，初始名字、类型、值和说明相同，ID 各自独立；主题依赖的公共 Set 不作为该领域的列。已有格只改 value，保留身份及其他字段；填空格取当前领域该行的名字、类型、说明，并生成新身份。App 和 CLI 调用同一领域逻辑，格式转换不得改变复合值的含义或共享可变对象。
9. **命名与维护。** 创建、重命名、删除和引用变更保持原子性，遵守 App 模型。未知目标、歧义名称、重复选择和引用问题给出可定位错误，不静默猜测。旧项目的命名和原生路径不能因只读调用被改写；引用无法安全维护时明确拒绝并说明受影响目标。
10. **复用策略。** AI 指南要求先查 Token 和组件，尽量复用并绑定 Token，缺少合适定义时再创建。工具允许直接值，写入结果只附本次相关的少量复用提醒，其余问题给总量和查询入口。不得按同值合并掉需要独立表达的 Token。
11. **组件与实例。** 样式、尺寸和状态差异优先使用同一组件的变体；文案等实例内容通过实例覆盖设置。“保存”“取消”不各自增加组件库条目。嵌套、实例选择、覆盖及引用传播沿用 App 规则。设计系统页由源数据自动生成并展示代表样例，代表样例不代替全部必要变体的检查。
12. **主变体规则。** 只指定组件、未指定变体时采用 App 主变体。SmallPen 的现有顺序映射使它对应 canonical 变体列表的第一项，重排会改变主变体；不新增独立默认变体字段。页面实例按自身保存的选择匹配，失效选择应诊断，不能静默以主变体替代。输出说明实际选中的变体及属性。
13. **局部编辑。** 组件、变体、页面、节点和交互均支持按目标修改字段或局部结构。程序维护完整合法对象、父子关系、引用和必要布局，不要求 AI 因单点修改重新提交整个组件或页面。未涉及的目标、字段和身份保持稳定。
14. **页面、布局和资源。** Screen 表达界面，Presentation 表达其一种结构布局；需要数值差异时可由 Token 主题解决。支持 SmallPen App 实际可持久化、可呈现的节点、布局、样式、文本、素材、字体及相关配置。素材和字体的创建、读取、修改和删除规则须公开；仅继承菜单或允许存字段不算能力已支持。
15. **交互设置。** AI 可以设置原型起点、源元素、触发方式、动作、目标，以及 App 已支持的动画等配置，并局部修改或删除连接。已有 App 点击、鼠标进入或离开、延时、跳转、浮层、返回及外部链接等交互要有真实可用的契约。条件与联动按实际支持的语义执行，不支持时明确报错，不能保存后忽略。
16. **流程表达与执行。** 原型起点和页面交互沿用 App 模型。画流程图的节点命令、具名交互引用集合与静态视图配置不能冒充可执行流程。读取以页面、交互元素、触发、动作、连接目标及联动为中心；逐步验证按指定步骤执行，返回操作、结果及相关变化。失败定位步骤、期望和实际结果。运行中的临时状态不作为设计写入，不改变 App 查看组合。
17. **文字与图片输出。** 文字描述解释区域、布局、实例内容和实际差异，默认折叠实例内部零件，按目标展开。文字线稿可用于组件、整页和局部，保留真实换行及对齐空格，按等宽文本读取；JSON 的转义换行应解码显示，文本文件使用真实换行。PNG 是实际渲染文件，局部查看保留正确背景与裁剪。
18. **统一投影。** 查看、检查和导出共用目标选择、领域组合和设计解析结果。结构布局选择不暗中替代本次 Token 选择。输出包含目标、实际选择、项目版本和必要来源；渲染指纹未变时可复用已看过的图片。
19. **检查范围。** 默认仅检查明确目标和本次组合，不自动检查全部组件、全部页面、全部变体或全部组合。组件 All 必须带单一组件目标，才检查其全部变体；不得提供跨所有组件或全项目的 All。页面及配置的检查同样限定指定页面；显式配置扩展参数具体展开哪些已有配置必须在契约和覆盖报告中说明。All 不自动扩大领域组合。
20. **检查职责。** 程序检查数据、引用、Token、绑定、失效实例、交互以及可计算的文字和布局问题。报告区分确定问题、提示、已通过、未检查和无法检查；可能的重叠不能不分意图直接当作确定错误。复杂背景、缺失资源和未支持交互等边界必须说明，不能以数据有效表示视觉和流程全部通过。
21. **结果大小。** 输出先给状态、目标、覆盖、问题总量及少量详情，详情可分页或按子目标读取。分页不减少实际检查覆盖，不截断 JSON，也不把未检查误报通过。文字线稿超预算时给摘要、完整文件或缩小范围指引，不从中间截断图框或默默折行。导出返回路径、大小及相应尺寸、版本和指纹。
22. **写入与恢复。** 写入是有版本保护的原子操作，同次写入的合法重试保持幂等，不重复生成对象；不同请求不能误用同一身份。拒绝操作明确说明是否写入。返回本次差异、受影响对象及可执行的反向修改说明，恢复是明确的新写入，不把历史回滚作为常规功能，也不替换 App 自身已有的撤销行为。
23. **AI 工作流程。** 项目启动先读设计系统；Token 增改后检查；组件完成后文字检查，一批完成后按需看设计系统；页面分块修改、查看和检查；流程配置后读连接并按需验证；最后检查项目需要的组合并导出。主题组查询应足够轻量，可贯穿整个流程。维护从变更及受影响对象开始，不反复重读完整项目。

## Testing Decisions

测试边界已由用户确认：以现有 CLI 黑盒集成入口验收命令、持久化、检查和导出，再用现有 App 矩阵及投影测试核对两端共用规则。本轮只记录测试方案，不运行测试或盲测。

- **主要入口。** 复用已有 CLI 子进程测试：创建隔离的临时 SmallPen 包，执行真实命令，核对退出状态、结构化返回、读回结果及导出文件。优先在这个最高公共入口增加行为验收，不为各内部函数新建测试接口。
- **行为断言。** 测试外部结果和不变量，避免断言内部调用次数、私有函数或实现顺序。使用真实解析、持久化和渲染；同一测试自己持有状态，失败能指出目标、组合和预期行为。
- **规则对照。** CLI 集成不能单独证明 App 行为一致。补充现有 App Token 矩阵事件、SmallPen 投影及会话测试，使用相同领域案例核对新增行、改格、填空、默认、主变体、实例选择和交互配置。保留原生身份与值类型的检查。
- **既有测试参照。** 复用 CLI workflow、CLI parameter contract、CLI help/schema、Token authoring、adapter variants、web projection、render、local-package、multiwriter session、App Token matrix 和 App projection 的现有测试方式，不复制其内部实现作期望值。
- **新增执行能力。** 流程逐步验证从实际公开 CLI 入口验收，配置一段可执行交互后核对每步结果。与 App 的执行或投影语义做必要对照，避免为测试另造一个与真实原型行为不同的模拟器。

## Further Notes

本规格覆盖整个 AI CLI 工作流。此前围绕主题、Token、输出和检查的实现与测试只代表阶段状态，不能据此宣称完整规格已完成。本文区分期望行为与当前实现事实；当前不冻结全部命令拼写，也不记录临时文件位置。

规格生成时，源码核对发现以下缺口。这些是历史背景；其处理和验收结果已记入本地计划：

- 组件叶节点有局部字段更新，但内部结构修改仍有整变体提交要求。
- 部分布局属性可保存，但 CLI 重排行为覆盖有限，需要补齐真实支持或明确诊断。
- 素材和字体入口已有基础能力，公开契约仍有只说明外层对象的地方。
- 现有 flow 命令主要添加流程图节点；原型起点、原生交互和 canonical 交互的公开契约与执行语义没有完全一致。
- 部分交互条件在转换时未生效，部分触发和动作不能投影；没有完整的 CLI 逐步执行检查入口。
- 现有组件默认选第一变体与 App 主变体规则一致，仍缺明确的单组件 All 能力及范围说明。
- 文字导出主要依赖结构大纲，文字线稿目标范围有限，仍需完善语义描述、范围和换行契约。
- 已有逆向批次机制需要与“差异说明加新的反向修改”对齐；Token 高层意图的重试分类已有未修复的失败回归证据。

本次仅在本地完成规格与实现。用户授权“可以实现了”后，已完成公开 CLI 的设置、读取、局部编辑、连接与逐步验证、范围检查及导出，并同步 help/schema/workflow。878 项 SmallPen 回归、App 矩阵与投影测试及独立 CLI 产物验收通过。复杂原生布局在本地投影仍有计算边界，会明确诊断并列出未覆盖项；逐步验证不播放动画像素。盲测仍按此前指示暂停，后续恢复以用户指示为准。

## 渐进式 CLI 帮助验收补充

- 根帮助只给简短导航；默认根帮助与每条命令帮助低于 2 KiB，不一次列全命令、参数表或完整工作流。
- `help workflow` 先列阶段，`help workflow STAGE` 只展开当前阶段；共用规则通过 `help rules RULE` 单独读取。
- `help COMMAND` 说明用途、简短用法和下一条查询；`schema command COMMAND` 提供精确参数契约。
- 有多个动作的 intent 先返回动作目录；指定动作后才给字段与示例。页面与流程节点绘制共用 `schema page` 输入说明。
- 命令与底层操作目录默认分页；完整手册、完整目录仍可用显式 `--full` 请求。所有机器 JSON 均保持压缩。
- 验收自动执行目录给出的帮助、动作和参数查询，核对尺寸、语义和示例，并重新实跑全部公开命令。结果页用大 Dialog 展示真实输入、stdout、stderr 与文件。
- AI 盲测仍暂停，本轮执行确定性的黑盒命令验收。
